# [IMT] IMMORTAL — บอต Discord เช็กชื่อ / ประวัติ / ส่งของ / ตู้แก๊ง (v1.4)

บอตภาษาไทยสำหรับสมาชิกแก๊ง แสดง **โลโก้ IMMORTAL** ในแผงและรายงาน แยกสามห้องดังนี้

1. `#เช็คชื่อรายวัน` — เปิดให้ **มา 18:00–23:59 น.** และ **มาสาย/ลา 00:00–23:59 น.** (Asia/Bangkok) ใช้บัญชี Discord จริง; เวลาเริ่มนับสายและส่งสรุปเริ่มต้น **20:00 น.** กรณีมา 20:01 แสดงสาย 1 นาที, 20:10 สาย 10 นาที แต่ยังอยู่ในกลุ่ม **มา** หากเลือกปุ่มมาเอง
2. `#เช็คของรายวัน` — ระบบตรวจของเดิมตามจำนวนที่ควรมี *ต่อสมาชิกหนึ่งคน* (`/item` และ `/checkitem`)
3. `#ส่งของ` — สมาชิกกดปุ่มเพื่อกรอก **ชื่อของ + จำนวน** และกดยืนยันอีกครั้ง จึงโพสต์รายการพร้อมรีแอ็กชัน ✅ ❌ สำหรับผู้ดูแล; มี **รายงานสด** ที่บอตแก้ไขข้อความเดิมเมื่อมีการส่งและตรวจรับ

**สรุปส่งของ:** ✅ ส่งแล้ว (ทุกรายการปัจจุบันผ่านการตรวจ), ❌ ขาดส่ง (มีรายการถูกปฏิเสธ หรือไม่เคยส่งภายในกำหนดเวลา), ⏳ รอตรวจ และ ⬜ ยังไม่ส่งก่อนกำหนดเวลา. หากจะให้แสดงคนที่ไม่ได้ส่งเลย ต้องเปิด Server Members Intent และกำหนด Role ของสมาชิกให้ครบ

**ตู้แก๊ง:** `/locker add`, `/locker edit`, `/locker remove`, `/locker list` จัดการสต็อกส่วนกลาง. เมื่อผู้ดูแลกด ✅ รับรายการส่งของ บอตจะเพิ่มจำนวนในตู้แก๊ง **อัตโนมัติ** (หากยังไม่มีชื่อของนี้จะสร้างรายการใหม่) หากเปลี่ยนเป็น ❌ จะย้อนจำนวนที่เคยรับ. ถ้าจำนวนในตู้ถูกปรับให้ต่ำกว่าปริมาณที่จะย้อน ระบบจะไม่ยอมให้ยอดติดลบและแจ้งให้แก้ยอดก่อน. โปรดหลีกเลี่ยงการบันทึกยอดซ้ำด้วย `/locker add` สำหรับของที่รับผ่าน ✅ แล้ว

## ใหม่ใน v1.4: เวลาเช็กชื่อ ลาหลายวัน และประวัติที่ลบข้อความหลัง 5 นาที

**เวลาไทย (Asia/Bangkok)**

- `✅ มา` เปิด **18:00–23:59 น.** ทุกวัน; 20:00 ถือว่าไม่สาย เมื่อกำหนดเวลาเริ่มนับสายเป็น 20:00; มา 20:01 = สาย 1 นาที
- `🕒 มาสาย` และ `📝 ลา` แจ้งได้ **ตั้งแต่ 00:00–23:59 น.** ของทุกวัน รวมถึงก่อนเวลา 18:00 น. มาสายก่อนกำหนดแสดงเป็น **แจ้งมาสายล่วงหน้า** พร้อมเหตุผล
- การลาเลือกวันแรกและวันสุดท้าย **นับรวมทุกวัน** เช่น 22/09/2569–23/09/2569 คือ **2 วัน**; แจ้งลาวันนี้หรืออนาคตล่วงหน้าได้ไม่เกิน 90 วัน และลา 1 ครั้งไม่เกิน 31 วัน; ไม่อนุญาตให้สมาชิกย้อนหลังเอง
- ปุ่ม `ลา` แสดงแบบฟอร์ม 3 ช่อง: วันเริ่ม (`2026-09-22` หรือ `22/09/2569`), วันสุดท้าย, เหตุผล (3–250 ตัวอักษร) แล้วแสดงหน้า **ตรวจสอบก่อนยืนยัน** ซึ่งบอกชัดเจนว่าจะทับข้อมูลวันใดหรือไม่
- กด `มา` ก่อนเวลา 18:00 น. จะไม่บันทึก แต่กด `มาสาย` / `ลา` ได้; การบันทึกหลัง 23:59 น. เป็นข้อมูลของวันถัดไป ไม่ย้อนวันโดยอัตโนมัติ

**ตัวอย่างคำสั่ง** (ใน Discord พิมพ์ `/` แล้วเลือกชื่อคำสั่งและกรอกช่องตามแบบฟอร์ม)

- `/leave start:26/09/2569 end:27/09/2569 reason:ไม่สบาย` — ตัวอย่างวันในอนาคต; ใช้วันที่ปัจจุบันหรือวันในอนาคตเท่านั้น
- `/history` — ดูประวัติตนเอง
- `/history member:@สมาชิก A` — ดูประวัติสมาชิกที่ระบุ

```text
✅ มา (1 ครั้ง)

🕒 มาสาย (1 ครั้ง)

📝 ลา (2 ครั้ง)

2. 22/9/2569 ลาเหตุผล ไม่สบาย
⬜ ไม่เช็กชื่อ (1 ครั้ง)
1. 20/9/2569 ไม่เช็กชื่อ
```

- `/history` ตอบเป็น **ข้อความสาธารณะในห้องที่เรียก** พร้อมปุ่มเปลี่ยนหน้าถ้ารายการยาว ข้อความและปุ่ม **ถูกลบหลัง 5 นาที** แต่ข้อมูลใน `data/db.json` **ไม่ถูกลบ** เรียกดูใหม่ได้ตลอดเวลา
- บอตบันทึกเวลาหมดอายุของข้อความไว้ในฐานข้อมูลชั่วคราวและตรวจสอบหลังเริ่มบอตใหม่ ถ้าปิดบอตตอนครบ 5 นาที ข้อความจะถูกลบเมื่อบอตกลับมาออนไลน์และมีสิทธิ์เข้าถึงห้อง
- เพื่อให้ลบข้อความหลังรีสตาร์ตได้ ให้บอตมีสิทธิ์ **ดูช่อง, อ่านประวัติข้อความ, จัดการข้อความ** ในห้องที่ใช้ `/history`; โดยปกติแนะนำให้เรียกใน `#เช็คชื่อรายวัน`
- **ยอด “ไม่เช็กชื่อ” ต้องมีหลักฐาน**: เปิด `Server Members Intent` ในหน้าบอต และตั้ง `ENABLE_MEMBERS_INTENT=true` ใน `.env`; บอตจะเก็บรายชื่อ Role ณ **23:59 น.** ของแต่ละวันที่ออนไลน์อยู่ แล้ววันถัดไปจึงนับคนที่ไม่บันทึกสถานะ. หากไม่ได้เปิดสิทธิ์ หรือบอตปิดในเวลาเก็บรายชื่อ จะ **ไม่นับวันนั้นเป็นขาด** แทนการเดารายชื่อย้อนหลัง. ประวัติการมา/สาย/ลาจาก v1.3 ยังอยู่ครบตามข้อมูลเก่า
- ผู้ใช้หนึ่งคนมีเพียง **หนึ่งสถานะหลักต่อวัน** หากแก้ไขสถานะ ระบบจะบันทึกสถานะล่าสุดในประวัติ ส่วนวันลาแต่ละวันนับหนึ่งครั้ง; เมื่อถึง 18:00 น. บอตสร้างรายงานสดของวันใหม่เพื่อแสดงวันลาที่แจ้งล่วงหน้าโดยอัตโนมัติ

## อัปเดตจาก v1.1 / v1.2 / v1.3 โดยไม่เสียข้อมูล

1. **หยุดบอตเก่า** โดยกด `Ctrl + C`. อย่าให้สองเวอร์ชันเขียนไฟล์ฐานข้อมูลเดียวกันพร้อมกัน
2. **เก็บไฟล์ `.env` และ `data/db.json` เดิมไว้**; สำรองสองไฟล์นี้แยกก่อนติดตั้ง. แตก ZIP รุ่นใหม่ แล้วคัดลอกสองไฟล์เดิมมาไว้ในโฟลเดอร์ `team-daily-discord-bot` ของรุ่นใหม่ โดย *ไม่ใช้* `.env.example` ทับ `.env` เดิม. ห้ามเผยแพร่ Bot Token
3. เปิด PowerShell ในโฟลเดอร์ใหม่ (ที่มี `package.json`) แล้วรัน:

   ```powershell
   npm.cmd install
   npm.cmd run register
   npm.cmd start
   ```

4. ถ้าบอตขึ้น `ออนไลน์แล้ว` ให้สร้างห้องข้อความ `#ส่งของ` แล้วใช้ `/delivery setchannel` กำหนดห้องใหม่ **ไม่ต้องตั้ง `/setup` ใหม่** ถ้าเคยตั้งห้องเช็กชื่อ/เช็กของและ Role ไว้แล้ว
5. ใช้ `/delivery panel` เพื่อให้บอตส่งปุ่ม **ส่งของ** และสร้างรายงานสดในห้องนั้น; ใช้ `/panel` ประเภทเช็กชื่อเพื่อแสดงหน้าปุ่มและเพิ่มโลโก้

หากคุณไม่เคย `/setup` ให้ใช้ `/setup` เลือกห้องเช็กชื่อ ห้องเช็กของ Role และตั้งเวลา `20:00` ได้ พร้อมเลือกห้องส่งของแบบไม่บังคับ หรือใช้ `/delivery setchannel` แยกภายหลัง

## ใช้รีแอ็กชัน ✅ / ❌ ในห้องส่งของอย่างไร

เมื่อสมาชิกยืนยันส่งของ บอตโพสต์ข้อความหนึ่งรายการต่อหนึ่งข้อความ ตัวอย่าง:

`1. @สมาชิก A — [ เงิน ] — [ 1,000,000 ]  ✅ ❌` 

เฉพาะ **เจ้าของเซิร์ฟเวอร์หรือสมาชิกที่มีสิทธิ์จัดการเซิร์ฟเวอร์** เท่านั้นที่กดอนุมัติหรือปฏิเสธได้ ผู้ที่ไม่มีสิทธิ์กดจะไม่เปลี่ยนข้อมูล. การตรวจรับสำเร็จจะแก้ข้อความเป็น ✅ ส่งแล้ว, ปฏิเสธเป็น ❌ ขาดส่ง และอัปเดตรายงานสดทันที. รายการที่ถูกปฏิเสธสามารถส่งใหม่ได้; รายการเก่าจะมีประวัติอยู่ แต่ไม่นับซ้ำในสรุป

ให้บอตมีสิทธิ์ **ดูช่อง, ส่งข้อความ, ฝังลิงก์, แนบไฟล์, อ่านประวัติข้อความ, เพิ่มรีแอ็กชัน และจัดการข้อความ** ในสามห้องที่ใช้. สิทธิ์จัดการข้อความจำเป็นต่อการลบรีแอ็กชันของผู้กดหลังบันทึก เพื่อให้แก้ผลการตรวจได้. ไม่จำเป็นต้องให้บอตเป็น Administrator.

## ตั้งค่าสิทธิ์รายชื่อสมาชิก (สำคัญสำหรับ “ยังไม่เช็ก/ขาดส่ง”)

ค่าเริ่มต้นบอตไม่ร้องขอสิทธิ์พิเศษ จึงออนไลน์ได้แม้ยังไม่เปิดการอ่านรายชื่อสมาชิก. ในกรณีนี้สรุปจะแสดงชื่อผู้ที่เคยกด/เคยส่งเท่านั้น และ **ไม่สามารถรู้ว่าใครบ้างที่ไม่ได้กดเลย** หากต้องการรายชื่อครบ ให้เข้า Discord Developer Portal → Bot → Privileged Gateway Intents → เปิด **Server Members Intent** และกดบันทึก จากนั้นเพิ่มบรรทัด `ENABLE_MEMBERS_INTENT=true` ในไฟล์ `.env` แล้วรีสตาร์ตบอต. แจก Role ที่เลือกใน `/setup` ให้สมาชิกทุกคนก่อนเช็กจริง

**ข้อควรระวัง:** อย่าเพิ่ม `ENABLE_MEMBERS_INTENT=true` หากยังไม่เปิดสิทธิ์ใน Developer Portal เพราะจะขึ้น `Used disallowed intents` อีกครั้ง. ไม่จำเป็นต้องเปิด Message Content Intent หรือ Presence Intent

## ความเป็นส่วนตัวและความต่อเนื่อง

- บอตไม่ใช้ Google Forms, Google Sheets, Make, Webhook หรือเว็บไซต์รายงานอื่น ข้อมูลเก็บใน `data/db.json` บนเครื่องที่รันและแสดงในเซิร์ฟเวอร์ Discord เท่านั้น. Discord ยังคงประมวลผลข้อความตามปกติในบริการของตนเอง
- สร้างข้อมูลจาก Discord User ID ของผู้กดโดยอัตโนมัติ ไม่เปิดให้ส่งแทนคนอื่นผ่านปุ่ม. ผู้ดูแลมีสิทธิ์ตรวจรับของ แต่การกดรีแอ็กชันไม่ได้ยืนยันว่ารับของจริงทางกายภาพ
- กดมาได้ 18:00–23:59 น. ส่วนแจ้งมาสายและลาได้ 00:00–23:59 น. ตามเวลาไทย; แจ้งมาสายก่อนกำหนดจะแสดงว่า “แจ้งมาสายล่วงหน้า”; รายงานสดอัปเดตจนสิ้นวัน แม้ส่งสรุปเวลา 20:00 น. แล้ว
- สมาชิกที่เลือก **มาสาย** หรือ **ลา** ต้องใส่เหตุผล แล้วทุกคนกดยืนยัน/ยกเลิกก่อนบันทึก. ปุ่มยืนยันหมดอายุใน 5 นาที
- รายการส่งของ **รอตรวจ** จนกว่าผู้ดูแลกด ✅ หรือ ❌; ไม่ถือว่ากดส่งแล้ว = ตรวจรับแล้ว
- บอตต้องทำงานค้างบน Windows หรือเซิร์ฟเวอร์ที่เปิดต่อเนื่อง. สำรองไฟล์ `data/db.json` และ `.env` ในที่ปลอดภัย อย่าใส่โทเคนลง GitHub หรือส่งภาพให้ผู้อื่น

## หากคำสั่งไม่ปรากฏ

หยุดบอตด้วย `Ctrl + C` แล้วรัน `npm.cmd run register` อีกครั้ง รอข้อความ “ติดตั้งคำสั่งสำเร็จ” จากนั้น `npm.cmd start` แล้วรีเฟรช Discord. หากขึ้น `50001 Missing Access` ให้ตรวจสอบว่าบอตถูกเชิญเข้าเซิร์ฟเวอร์ที่ตรงกับ `GUILD_ID` พร้อม `bot` และ `applications.commands`

**การทดสอบ:** มีชุดทดสอบตรรกะสำหรับเวลาไทย รายงาน ลาหลายวัน ประวัติ การยืนยันส่งของ การอัปเดตตู้แก๊ง การย้อนยอด และความเข้ากันได้ของข้อมูลเดิม. ยังต้องทดสอบการเชื่อมต่อจริงกับ Discord ของเซิร์ฟเวอร์คุณหลังติดตั้ง
